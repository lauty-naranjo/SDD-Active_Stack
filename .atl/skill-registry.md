## Compact Rules

Pre-digested rules per skill. Delegators copy matching blocks into sub-agent prompts as `## Project Standards (auto-resolved)`.

### supabase-postgres-best-practices
- Load BEFORE any Postgres schema/migration/RLS/index/query change — even one-column or single-query changes.
- Schema: right-sized types (timestamptz, uuid/bigint PKs), FKs always indexed, CHECK/UNIQUE/NOT NULL constraints, lowercase identifiers.
- Indexes: btree default; composite columns in leftmost-query order; partial indexes for filtered queries; covering (INCLUDE) to avoid heap fetches; GIN/GiST for jsonb, full-text, geo.
- RLS: enable on every user-facing table; least-privilege GRANTs; wrap `auth.uid()` calls for performance; never use SECURITY DEFINER to bypass RLS silently; always test tenant isolation.
- Connections: pool via Supavisor/pgbouncer (transaction mode), cap max connections, set idle timeouts, prefer prepared statements.
- Concurrency: keep transactions short; lock tables in consistent order; `SELECT ... FOR UPDATE SKIP LOCKED` for queues; advisory locks (`pg_advisory_xact_lock`) for app-level mutual exclusion.
- Data access: batch inserts; `ON CONFLICT` upserts; keyset pagination (never large OFFSET); join eagerly to kill N+1.
- Diagnose with `EXPLAIN (ANALYZE, BUFFERS)` + `pg_stat_statements`; keep VACUUM/ANALYZE healthy.
- Agenda anti-solapamiento (C-04): enforce in the DB — exclusion constraint on `tstzrange` + GiST or serializable transaction + unique index — never application-code-only.

### vercel-react-best-practices
- Eliminate waterfalls (CRITICAL): `Promise.all()` independent fetches; start promises early, await late; Suspense boundaries to stream; never sequential awaits for independent data.
- Bundle (CRITICAL): import directly, never barrel files; `next/dynamic` for heavy components; statically analyzable import paths; defer analytics/logging until after hydration; load modules only when the feature activates.
- Server: `React.cache()` per-request dedup; LRU for cross-request cache; minimize RSC→Client serialized props; no module-level mutable request state; `after()` for non-blocking work; authenticate server actions like API routes.
- Client fetching: SWR for dedup; dedupe global listeners; passive scroll listeners; versioned, minimal localStorage.
- Re-renders: memoize only expensive components; derive state during render (not effects); functional setState; primitive effect deps; `startTransition`/`useDeferredValue` for non-urgent updates; never define components inside components.
- Rendering: `content-visibility` for long lists; hoist static JSX; ternary (not `&&`) for conditionals; `useTransition` for loading state; defer/async scripts; React DOM resource hints for preloads.

### tdd
- Red before green: write the failing test first, then only enough code to pass — no speculative features.
- Test ONLY at pre-agreed seams (public boundaries); confirm seams with the user before writing any test ("What's the public interface, which seams?").
- Tests verify behavior through public interfaces and must survive refactors; never test privates/mocks of internals/DB side-channels.
- Expected values come from an independent source of truth (literal, worked example, spec) — never recompute the way the code does (no tautological assertions).
- One vertical slice per cycle (one seam → one test → one minimal implementation, tracer bullet); never bulk-write all tests first (no horizontal slicing).
- Refactoring belongs to review stage, not the red→green loop.
- Project-critical cycles: concurrencia de agenda (doble reserva → 1 gana), doble reclamo de waitlist, webhooks MP/ARCA idempotentes.

### webapp-testing
- Write native Python Playwright scripts with `sync_playwright()`; always Chromium headless; always `browser.close()`.
- Reconnaissance-then-action: `goto` → `wait_for_load_state('networkidle')` FIRST → screenshot/DOM inspect → identify selectors → act. Never inspect DOM before networkidle on dynamic apps.
- Static HTML: read the file directly for selectors instead of booting a server.
- Server lifecycle: use `scripts/with_server.py` as a black box — run `--help` first, never read its source; supports multiple `--server/--port` pairs (backend + frontend).
- Automation scripts contain only Playwright logic (servers are managed by the helper).
- Prefer descriptive selectors (`role=`, `text=`, IDs); add explicit waits (`wait_for_selector`); capture console logs when debugging.
- Covers E2E for this project: reserva pública `/reservar` y `/turnos/:token` sin login, ventana 24h (bordes 23:59/24:01), deep-link `wa.me`.

### kb-creator
- Output ALWAYS goes to `knowledge-base/` at project root with the 10 canonical files + `README.md`; NEVER mix with `docs/` (sources live there).
- Mode A (docs/ has sources): silent fire-and-forget — no questions; ambiguities go to `10_preguntas_abiertas.md`, never invented values.
- Mode B (no sources): interactive senior-architect mode — 3-5 strategic questions, proposals with pros/cons, per-file validation.
- Extras allowed only as `1X_/2X_` kebab-case files; they complement, never replace, the 10 canonicals.
- Orchestrated: writes ONLY `state.kb` (source `ingest` or `interactive`).

### roadmap-generator
- Pre-checks mandatory: `knowledge-base/` + 10 canonicals + `openspec/` must exist, else stop with a clear message (no output).
- Output is ONE file: `CHANGES.md` at project root (not inside `openspec/`); section structure is a frozen contract — never add/remove top-level sections.
- Always read `04_modelo_de_datos` + `06_funcionalidades` + `07_flujos_principales` + `08_arquitectura_propuesta` first.
- C-01 is always foundation-setup; auth before protected resources; referenced entity before referrer; backend before coupled frontend; external integrations/payments/webhooks and admin/dashboards last.
- Codes sequential `C-01…C-NN` (2-digit pad), kebab-case names, no `us-NNN-` prefixes.
- Scope bullets are operational (models, endpoints, migration numbers, WS events, tests) — never vague descriptions.
- Orchestrated: writes ONLY `state.roadmap` (`created_by`, `source`, ordered `C-NN` list).

### discovery-research
- Converts "tengo una idea" into build-ready context BEFORE any KB exists; result feeds `kb-creator`, never replaces it.
- Workflow: sources → 11-point checklist Q&A → user-confirmed gate → write `discovery/discovery.md` + `state.discovery`.
- If URLs exist, dispatch `web-scraper` once per URL; never reimplement scraping here.
- Never ask what scraping already answered — show as summary for confirm/correct.
- Unverified assumptions become `riesgos`/`preguntas abiertas` entries (assumption-mapping logic, unnamed).
- NEVER write files or touch state before the user's explicit confirmation of the summary.
- Orchestrated: writes ONLY the top-level `state.discovery` section.

### web-scraper
- Output schema is fixed (8 fields, same order, always) → `discovery/sources/<slug>.md` (slug via `scripts/slugify.py`, reruns overwrite).
- Never invent data: missing fields stay `(no publicado)`.
- One URL at a time; report resolved vs failed at the end, never abort the batch on one failure.
- Read-only skill: no user-system writes, no approval gate needed per URL.
- No mass crawling/entire-site traversal; no evasion tricks on 403/paywall/CAPTCHA/heavy-JS shells — report the limitation and move on.

### find-skills
- Check the skills.sh leaderboard BEFORE running CLI search — prefer popular, battle-tested skills.
- `npx skills find [query] [--owner <owner>]` to search; `npx skills add <package>` only after user picks (installing globally is HIGH-governance — propose and wait).
- Scope the recommendation to the project's KB/CHANGES context (domain, stack, constraints like presupuesto cero).
- Record picks in `state.skills` (`recommended` with why, `installed`, `install_notes`); never install autonomously.

### active-orchestrator
- Thin orchestrator: NEVER reimplement a phase's logic — always route to its sub-skill (`Skill` for interactive, `Agent` for mechanical).
- Owns ONLY `version`, `step`, `owner` in state; sub-skills own their sections.
- NEVER ask strategic content questions (checklist content belongs to kb-creator/discovery-research); routing questions (e.g. whether to run Discovery) are allowed.
- Checkpoint at EVERY phase boundary: never advance `step` without explicit user "Continuar".
- Check sub-skill presence before dispatch; offer install, degrade gracefully if declined; NEVER install autonomously.
- Resume by default when state exists with `step != "done"`.
